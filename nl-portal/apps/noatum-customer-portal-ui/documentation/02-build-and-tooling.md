# Build and tooling

Everything needed to run, build, lint, test and ship this SPA. No business
context — see the parent repository's `/docs` for that.

---

## 1. Runtime and package manager

| | |
|---|---|
| Package name | `noatum-customer-portal-ui` |
| Module system | ESM (`"type": "module"`) |
| Bundler | Vite 8 |
| Framework | React 19.3 |
| Language | TypeScript (see §5 for the unusual pinning) |
| Package manager | pnpm, driven from the parent workspace |

This app is a **git submodule** inside the `noatum-customer-portal` parent
repository, attached at `apps/noatum-customer-portal-ui`. The parent owns the
pnpm workspace, the lockfile and the pipelines. `pnpm install` is run from the
parent, not from here.

## 3. Generated code — read this before your first build

`src/api/generated/` is **git-ignored and required**. Application source imports
from it, so a fresh checkout does not typecheck or build until it is produced:

```
src/api/generated/schema.d.ts        openapi-typescript output
src/api/generated/staff-role-form.ts generated by scripts/generate-staff-form.mjs
```

`scripts/generate-api.mjs` takes its input from one of two places:

- **default** — `http://127.0.0.1:43000/api/docs-json`, i.e. a running API;
- **`--offline`** — `../../noatum-customer-portal-api/openapi.json`, a **relative
  path that climbs out of this repository into the sibling submodule**.

That second path is the one CI uses, and it is worth being explicit about: this
app cannot generate its API client from its own repository alone. A standalone
clone of `noatum-customer-portal-ui` has no `openapi.json` to read. The contract
travels through the filesystem, not through a published package.

Both outputs come from the same document in one run, so the types and the
generated form schema can never describe different API versions.

> **Never hand-edit these files, and never hand-write a type that mirrors an API
> shape.** Regenerate instead. ESLint additionally forbids importing from the API
> app's source (§6).

## 4. Environment variables

`vite.config.ts` sets `envDir: false` and loads env files itself, mapping the
Vite mode to a file:

| Mode | File |
|---|---|
| `development` | `.env.local` |
| `uat` | `.env.uat` |
| `prod` / `production` | `.env.prod` |

Only keys beginning `VITE_` are injected, and `process.env` **overrides** the
file, so CI can set a value without editing anything on disk. All three env
files are git-ignored; there is no committed `.env.example`.

Keys in use:

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Origin of the REST API. Validated at runtime — see `06-data-layer.md` |
| `VITE_DEV_AUTH` | Offers seeded demo identities on the login screen. Development only |
| `VITE_ENTRA_STAFF_CLIENT_ID` | Entra app registration for Noatum staff sign-in |
| `VITE_ENTRA_STAFF_AUTHORITY` | Entra authority URL |
| `VITE_ENTRA_STAFF_API_SCOPE` | Scope requested for the API |
| `VITE_ENTRA_STAFF_REDIRECT_URI` | Must match a registered redirect URI exactly |
| `VITE_ENTRA_CUSTOMER_*` | Customer-side equivalents. Currently unset; the login screen reports the customer tab as unavailable while they are |
| `VITE_PUBLIC_API_MOCK` | `true` enables the in-browser stand-in for `/api/public/*`. **Opt-in** — absent means the real API |

Nothing secret belongs in any of these. They are compiled into the bundle and
are readable by anyone who loads the page.

## 5. TypeScript

`tsconfig.json` is deliberately self-contained — it extends nothing outside this
folder, so the app compiles if lifted out of the monorepo.

Notable settings beyond `strict`:

| Option | Effect |
|---|---|
| `noUncheckedIndexedAccess` | `array[0]` is `T \| undefined`. This is why `!` and `?? fallback` appear after index access throughout the codebase |
| `noImplicitOverride` | `override` keyword required |
| `noFallthroughCasesInSwitch` | |
| `isolatedModules` | Forces `import type` for type-only imports (also enforced by lint) |
| `moduleResolution: "bundler"` | |
| `paths: { "@/*": ["./src/*"] }` | Mirrored in `vite.config.ts`; **change both or the editor and the bundler disagree** |

`include` covers `src/**/*`, `e2e/**/*` and `vite.config.ts`.

**Unusual dependency pinning.** `package.json` resolves `typescript` to
`npm:@typescript/typescript6@6.0.2` and adds `@typescript/native` as
`npm:typescript@7.0.2`. If `tsc` behaves unexpectedly, check which binary is
actually on the path before assuming a code fault.

## 6. Linting

Two files work together:

- **`.eslintrc.cjs`** — legacy-format object holding `settings`, `ignorePatterns`
  and the project's own `rules`. It is not used directly by ESLint 10.
- **`eslint.config.cjs`** — the flat config that ESLint actually reads. It
  imports the legacy file and re-applies its rules and settings on top of the
  shared configs.

The flat config composes, in order:

1. every **built-in ESLint rule marked `recommended`**, set to `error`
2. `@typescript-eslint` flat recommended
3. `eslint-plugin-react` flat recommended, wrapped in a shim that re-adds the
   removed `context.getFilename()` / `context.getSourceCode()` APIs
4. `eslint-plugin-react-hooks` flat recommended
5. `eslint-config-prettier` (turns off stylistic rules)
6. the project rules from `.eslintrc.cjs`

Project rules worth knowing:

| Rule | Setting |
|---|---|
| `react/react-in-jsx-scope` | off (React 19 JSX transform) |
| `react/prop-types` | off |
| `@typescript-eslint/no-unused-vars` | error, with `^_` ignore pattern for both args and vars |
| `@typescript-eslint/consistent-type-imports` | **error** — type-only imports must use `import type` |
| `no-console` | warn; `console.warn` and `console.error` allowed |
| `no-restricted-imports` | **error** — see below |

**Import restrictions.** Two patterns are blocked outright:

- `**/noatum-customer-portal-api/src/**` and `noatum-customer-portal-api` — the
  two apps deploy separately and share no code. Generate the client instead.
- `**/cw1-simulator/**` — the simulator is never imported by the SPA.

`react-hooks` rules are errors, not warnings, and two in particular shape the
code in this repository: `set-state-in-effect` and `incompatible-library`. See
`11-conventions.md` for the patterns used to satisfy them.

Ignored paths: `dist`, `node_modules`, `coverage`, `playwright-report`,
**`src/api/generated`**.

Because `lint` runs with `--max-warnings=0`, a warning fails the build exactly
like an error.

## 7. Formatting

`.prettierrc`:

```json
{ "semi": true, "singleQuote": true, "trailingComma": "all",
  "printWidth": 100, "tabWidth": 2, "arrowParens": "always", "endOfLine": "lf" }
```

`endOfLine: "lf"` matters on Windows: several files in the working tree are
checked out CRLF. Scripts that rewrite source must normalise to LF, edit, and
restore the original line endings, or every line shows as changed.

## 8. Vite configuration

`vite.config.ts` does four things beyond defaults:

1. **Manual env loading** (§4), because `envDir: false`.
2. **`@` alias** to `./src`, mirroring `tsconfig.json`.
3. **`@tailwindcss/vite`** — Tailwind v4, configured through CSS rather than a
   `tailwind.config.js`. There is no Tailwind config file; `components.json`
   points at `src/design-system/styles/foundation.css` as the Tailwind entry.
4. **A custom plugin, `noatum-locale-parity`**, which runs at `buildStart` and
   throws if `en-US.json` and `es-ES.json` have different key sets, or if any
   Spanish value is blank. **A missing translation fails the build**, not just
   the test suite.

Server port 45173. Build output `dist/`, sourcemaps enabled.

## 9. Tailwind and shadcn

Tailwind v4 is installed and wired through the Vite plugin, but the codebase is
overwhelmingly **CSS Modules**. Tailwind is present mainly to support
shadcn-style primitives.

`components.json` records the shadcn conventions:

| Setting | Value |
|---|---|
| `style` | `new-york` |
| `tailwind.css` | `src/design-system/styles/foundation.css` |
| `tailwind.config` | *(empty — v4 needs none)* |
| `cssVariables` | `true` |
| `iconLibrary` | `lucide` |
| alias `components` | `@/design-system/components` |
| alias `ui` | `@/design-system/primitives` |
| alias `utils` | `@/design-system/utils` |
| alias `lib` | `@/lib` |
| alias `hooks` | `@/hooks` |

A `shadcn add` therefore lands in `src/design-system/primitives`, not a
top-level `components/ui`.

## 10. Tests

| Kind | Runner | Location |
|---|---|---|
| Unit / component | Vitest + jsdom + Testing Library | `src/**/*.test.ts(x)`, `*.spec.ts` |
| End to end | Playwright | `e2e/` |

`test` explicitly excludes `e2e/**` so Vitest does not try to run Playwright
specs.

Playwright starts its **own** dev server on `127.0.0.1:45180` with
`--strictPort` and `reuseExistingServer: false`, so it never collides with a
developer's 45173. Two projects: `desktop` (1440×1000) and `mobile` (390×844,
`isMobile`, `hasTouch`). Traces are retained on failure.

See `10-testing.md` for what is actually covered, including the token and
stylesheet guards.

## 11. Entry point

`index.html` is minimal: `<div id="root">`, `<script type="module"
src="/src/main.tsx">`, `lang="en-US"`, and a static `<title>Noatum
Logistics</title>`.

There is no SSR and no per-route `<title>` handling. `public/` is empty.

## 12. Repository hygiene

`.gitignore` excludes `node_modules/`, `dist/`, `build/`, `*.tsbuildinfo`,
**`src/api/generated/`**, coverage and Playwright output, `.env` and `.env.*`,
logs, and editor folders.

`login-desktop.png`, `login-mobile.png`, and a `test-results/` directory.
