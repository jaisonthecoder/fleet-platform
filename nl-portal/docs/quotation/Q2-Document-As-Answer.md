# Q2 — A document can be the answer

| | |
| --- | --- |
| Goal | A branch that produces a PDF quote in its own template can still use the portal |
| Size | Small |
| Depends on | Q1 |
| Needs CargoWise | No |
| Needs a mockup | Only for the upload and download controls, which sit on the Q1 screen |

Some branches answer a quote with a document, not a number. There is no standard format, so
the portal must accept the document as the answer, with or without an amount.

---

## Database

New table `quote_document`:

| Column | Notes |
| --- | --- |
| `quote_id` | FK to `quote` |
| `customer_group_id` | **NOT NULL, indexed, RLS enabled and forced.** Pattern A |
| blob reference | The stored object name, generated by us |
| `filename` | As supplied, for display only. **Never used as a path** |
| `contentType`, `sizeBytes` | Validated server-side |
| `uploadedById`, `uploadedAt` | Who and when |
| `customerVisible` | boolean, default true |

Reversible migration with a `down.sql`.

---

## The rule that expresses the whole decision

> A quote may move to `quoted` with **an amount**, or with **at least one customer-visible
> document**, or **both**. Never with neither.

That single validation is the entire "no fixed format" decision, expressed in code. Put it
in the service, not in the database, and test all four combinations.

---

## API

- **Upload** behind `quotes.price`.
- **Download** behind `quotes.read`, plus a check that the document is customer-visible
  **and** belongs to the caller's group.
- Files go to **Azure Blob**. Never store file bytes in PostgreSQL.

---

## Security — this phase handles file upload, so be deliberate

- Validate **content type and size server-side**. A client-declared type is a claim, not a
  fact.
- **Generate the stored name yourself.** Never serve a blob from a client-supplied path or
  filename.
- A document with `customerVisible = false` must be **absent from every customer surface**:
  list, detail, export, notification, and any future API. Not hidden — absent.
- The download route must not leak existence. An out-of-scope document behaves exactly like
  one that does not exist.

---

## Tests to write, and leave unrun

- All four combinations of the `quoted` rule: amount only, document only, both, neither
- A foreign group's document cannot be downloaded
- A `customerVisible = false` document is absent from the customer list and detail
- Oversized and wrong-content-type uploads are refused
- One tenant-isolation test on `quote_document`

---

## Done when

A quote with a document and no amount reaches the customer correctly, and a quote with
neither is refused.

---

## Dependency to confirm before starting

An Azure Blob container and its credentials. If none is configured, say so and stop rather
than falling back to the database — a file column would be the hardest thing in this module
to undo later.
