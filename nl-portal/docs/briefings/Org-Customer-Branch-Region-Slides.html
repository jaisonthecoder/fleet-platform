Linking

One deliberate link, with a safety gate

  • Organisation level only. We link a whole organisation, never a single address.
  • One organisation, one customer. A code can never belong to two customers.
  • One customer, many organisations. Several offices can link to one customer.
  • Confirmed and active only. An unconfirmed organisation cannot be linked at all.

The gate is in the database

The link is a foreign key that only accepts a source-confirmed organisation. A wrong link cannot be created, even by mistake. The screen shows why an organisation is blocked: already linked, not yet confirmed, or inactive.

Identifying a staff member's branch

Where it is set, and how the portal knows it

Where a human sets it

Administration, then Staff users, then edit a person. The drawer has an Operating branch dropdown next to the roles. A pricing role cannot be granted without a branch, and every change is audited. The region is never picked here — it rides along with the branch.

How the portal reads it

At sign-in the identity lookup returns the branch code and name. It travels in the request and is returned by the profile endpoint, so every request already carries which office the person is from.

The detail that causes confusion

The word "branch" means two different things

In the pilot both are Madrid, which is why it looks like one thing. They are separate fields.

Staff branch

The office an employee works from. It scopes the pricing queue.

Servicing branch

The office that services a customer's linked organisation. Falls back to the customer default.

In one paragraph

What to take away

We keep three separate lists — the CargoWise directory we mirror read-only, the customer we onboard, and our own regions and branches. Onboarding is import, create, then link — one code to one customer, only confirmed organisations, enforced by the database. A staff member is tagged with one branch on the Staff users screen, and the region is whatever that branch belongs to. For the pilot, one region and one customer is data, so a second region later is configuration, not code. The internal journey is ready to demo today; the customer's own login and the live CargoWise feed are the two pieces still pending.
